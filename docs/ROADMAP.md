# Agent Observatory · 路线图

路线图解释产品方向和取舍；优先级、任务与验收集中在[根 TODO](../TODO.md)，当前架构见[架构说明](ARCHITECTURE.md)。

目标是让个人能够看到 agent 在任务上花了什么、交付了什么，并把复盘中有效的经验带到下一次任务。会话是证据，不是任务；能检索摘要，不等于已经确认知识。

## 推进顺序

| 阶段 | 期望结果 |
| --- | --- |
| 可信账本 | 如实呈现用量缺失与费用口径，修订和撤回能传到下游；增量结果与完整重建一致。 |
| 可靠日报 | 停机与迟到可补，删除可追踪，手写笔记不丢；模型失败也能看到已发生的消耗。 |
| 可用复盘 | 先手工关联任务与会话，在单项目里从结果追到成本和证据，再形成可复查的周行动项。 |
| 可信经验 | 人工确认生成候选后才作为经验复用；能看到适用条件、反例、实际反馈与撤回状态。 |

## 取舍

- 四个工具保持独立安装、按模块发布；Trace 是可选数据源。通过小范围版本化契约和共享金样例协作，不建强制总控平台或通用运行时。
- 先把数字、证据和自动运行做可靠，不优先扩充宿主、图表或引入向量数据库。状态视图应区分在线、追平、有覆盖三件事。
- 默认优先 metadata，正文只对明确授权项目开启。真实试点从小范围做起，不把更广的数据采集视作复盘质量的替代。
