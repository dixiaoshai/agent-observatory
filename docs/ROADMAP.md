## 优先的架构后续

1. Journal 将离线 source 配置与 Trace 配置显式分开，避免离线配置中仍需形式合法的 trace_url / token_env。
2. Journal 定义自定义活动的版本化修订、删除与较大数据流增量导入；当前仅完整不可变追加快照，不宣称全文件事务。
3. 自定义 Stats provider 按实际需求扩展费用、父子归属、来源覆盖和证据字段；不要把用户原始正文塞入 metadata。当前只支持标准化 session / turn / tool-name / token facts。
4. Knowledge 为更多受信任来源增加适配器；对远端分页来源，先构造一致完整快照，不能将缺页解释为删除。
5. 将 Stats 既有可选正文下钻从 Trace SQLite 直读迁到显式内容来源接口，逐步去除这项历史 schema 耦合；本次保留兼容，自定义使用可关闭。
6. 确认公共包名、许可证、组织与发布权限后再公开发布；按模块分别发版本。

## 继承的业务可信度工作

本次组织代码并补齐独立来源入口，不代表现有业务问题全部修复。需单独处理并验证：

- Trace 的同 event_id 修订与下游增量消费兼容性；消费后源文件重写的跨模块回归。
- 请求级 usage / cost 缺失保护已完成首轮：pi/dsh 保留逐调用观测、已知小计与未知字段，实际请求总数/覆盖保持未知；旧归档需新库重建，不宣称已修复事件修订。验收见[验证记录](VALIDATION.md#请求级用量与费用覆盖2026-11-15)。
- Journal 漏日补跑与 stale 旧日更新、每日累计输出预算、失败调用消耗记账、map 缓存与恢复。
- Journal 逐条结论的证据绑定、Knowledge 的 generated 标记、候选经验审批及撤回闭环。
- Stats UTC 轮次分日与 Journal 本地事件分日的明确对齐。
- 长期真实宿主、断网/重启/权限故障矩阵；真实模型质量评估。

这些项来自原工具体系的已知限制，不在此次架构整理中静默修改。历史文档提到的真实服务、真实日报与 launchd 验收不等于新副本已部署；本次只做合成数据验证，当前结果见[验证记录](VALIDATION.md)。
