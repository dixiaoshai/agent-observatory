# Agent Knowledge 架构

本文描述 Agent Knowledge 的当前结构和边界。当前实现面向本机单用户，提供文档与代码索引、词法检索、来源核验、归档执行证据消费、主动拉取 worker 和只读 MCP。

## 职责与范围

- **文档与代码检索**：只扫描配置中显式选择的源目录，保存原文片段、相对路径、行号、内容哈希和源版本；查询与直接读取都受本机身份和项目范围约束。
- **归档执行证据**：通过版本化 JSON content 批次消费 [agent-trace](../../agent-trace/README.md) 的执行事件，维护独立证据库、事件引用、事务游标和项目消费范围。归档证据是历史观察，不会自动晋升为确认知识。
- **主动拉取**：独立 worker 从 Trace 的本机只读 API 续读 content 页，不依赖 MCP 连接，也不由 Trace 运行本项目命令。
- **未实现能力**：对话记忆提取、模型提供方、经验候选与反馈、事件/任务队列、自动 skill 修改、团队多用户权限。未实现的能力不代表已经可用。

## 模块边界

### 与 Trace

Trace 负责执行日志的采集、原始事件快照、统一事件和删除流。Knowledge 只通过两种方式接触它：

1. 手动 `archive-import` 导入 content 批次；
2. `follow` worker 通过 `GET /v1/status` 和 `GET /v1/events` 主动拉取 content 页。

双方不读取归档内部 SQLite，也不写入对方数据库。Knowledge 自己维护业务游标、页面指纹、单 worker 租约和故障重试；Trace 不保存投递状态。metadata 与 content 契约分离，Knowledge 只消费 content 视图，归档为 metadata 模式时以 `VIEW_UNAVAILABLE` 永久失败。

### 与 Agent Journal

每日回顾和跨天经验整合由独立的 [Agent Journal](../../agent-journal/README.md) 负责；它消费 Trace content、维护自己的游标、日缓冲和模型调用。Knowledge 不读它的数据库、不调它的命令，只在 Journal 把日报写入 Markdown 目录后按普通 source 索引。该 source 需要 `generated: true` 标记来区分模型生成物与来源事实；标记尚未实现，因此日报当前不应作为已确认知识被索引。

### 与 Agent Stats

Knowledge 当前没有模型调用，也没有用量输出或 Agent Stats 接入；Stats 不参与保存记忆、检索或事务决策。两者是独立模块，不共享数据库。

## 主动拉取（follow）

采用无 hook 的方案：Trace 常驻提供只读 v1 事件流，Knowledge 在自身项目维护自动拉取 worker、消费进度、重试与授权检查。

- `src/follow/config.ts` 严格校验 follow 配置：回环 `http://host:port`、固定 `content` 视图、`token_env` 环境变量名、未知字段拒绝、相对路径按配置文件解析。
- `src/follow/client.ts` 实现本机 HTTP 客户端：不跟随重定向、不使用代理、限制响应大小、按状态码区分临时与永久错误，并识别 `Retry-After`。
- `src/follow/worker.ts` 负责身份探测、分页拉取、指数退避、单 worker 租约和优雅停止。每页复用 `ArchiveEvidenceStore.importBatch`，把证据投影、墓碑、页面指纹和归档游标放在同一本地事务提交。
- worker 与 MCP 连接生命周期分离：关闭聊天不会停止同步，不运行 MCP 时也可以单独运行 follow。
- 证据仍进入独立证据库，不自动转为确认知识，也不引入模型提取。

## 技术结构

当前本地实现使用 TypeScript 和 SQLite。SQLite 保存权威记录、源版本、证据、页面指纹、游标和审计；搜索索引是可重建的派生数据。原始资料仍由源文件及其版本定义。

```text
文档/代码适配器（内置 SourceScanner）      Trace content 批次（archive-import / follow）
        │                                        │
        └──────────── 标准化输入 ────────────────┘
                            │
        Core：来源、记录、证据、作用域、生命周期
                            │
        SQLite：事务、源版本、游标、派生检索索引、审计
                            │
        Retrieval：作用域过滤、词法召回、排序、新鲜度校验
                            │
                 CLI / 只读 MCP（STDIO）
```

- 本机各组件在同一代码库内组织，通过组合入口 `bootstrap` 装配。
- CLI 与 MCP 可以独立启动、共用同一个数据库文件；归档证据使用单独的投影库，避免同步导入阻塞异步知识事务。
- 宿主 hook 不参与当前链路。

## 模块责任

| 模块 | 责任 | 当前状态 |
| --- | --- | --- |
| `core` | 统一记录信封、来源、证据、作用域与生命周期规则；不依赖数据库、宿主或传输协议 | 已实现 |
| `application` | 用例编排与所需端口定义；同步、检索、读取、删除、重建索引 | 已实现 |
| `storage` | 实现应用层存储接口；SQLite schema、事务、版本与删除 | 已实现 |
| `ingestion` | 文件发现、路径限制、内容哈希、忽略规则、增量更新与删除 | 已实现 |
| `retrieval` | 作用域内的 BM25 风格词法召回与排序 | 已实现 |
| `archive` | 归档证据批次导入、页面幂等、墓碑、项目消费范围、follow 状态与租约 | 已实现 |
| `follow` | 严格配置、本机 HTTP 客户端、拉取 worker | 已实现 |
| `interfaces` | CLI 与 STDIO MCP；调用同一应用服务 | 已实现 |
| `extraction` | 文档/对话提取器、AST 解析、模型输出校验 | 未实现 |
| `learning` | 候选经验、冲突处理、验证反馈、晋升与撤回 | 未实现 |
| `adapters` | 宿主事件转换与其他 agent 的能力差异 | 未实现 |
| `telemetry` | 模型用量事件与输出适配器 | 未实现 |

模块是代码边界，不是必须拆分的微服务。

## 高内聚与低耦合约束

- 依赖方向由入口/适配器指向应用用例，再指向领域；存储、搜索和扫描实现由组合入口注入。
- 领域与应用代码不导入具体数据库驱动、宿主 SDK 或 Agent Stats 实现。
- 对外只暴露模块公共接口和领域数据；其他模块不得跨目录访问内部 helper。
- 同一用例的规则集中在应用层：MCP、CLI 和未来入口不各自维护一套保存、权限或晋升规则。
- 新数据源、agent 和数据库通过增加适配器接入，不修改应用端口的使用方。

## 可替换的存储接口

接口定义放在应用层的 `ports` 中，由存储层实现。方法使用领域对象、游标和异步返回值；SQL、连接句柄和数据库专属错误保持在适配器内部。

| 接口 | 契约 |
| --- | --- |
| `SourceRepository` | 来源与不可变源版本、内容哈希、版本检查、文件替换与删除 |
| `RecordRepository` | 记录状态、归属、来源引用、按来源失效与删除 |
| `AuditRepository` | 审计追加、同步幂等回执 |
| `UnitOfWork` | 在同一事务内提供上述仓储；统一提交和回滚语义 |
| `LexicalSearchIndex` | 按作用域做词法检索和重建派生索引 |

当前应用端口只实现现有用例所需的来源、记录、审计、事务、扫描和词法索引。事件/任务仓储、经验反馈、模型调用和用量输出（`UsageSink`）尚未实现。

`UnitOfWork` 保证文件版本、记录、索引回执和同步审计原子提交。事务回调内不执行模型调用、外部网络或遥测发送，避免长事务和重试时的重复外部动作。更换或新增数据库后端时，应提供自己的 schema 变更和数据转换程序，并通过共同的仓储行为契约：原子事务、幂等、版本冲突、游标稳定、作用域与删除一致性。

## 检索与数据可靠性

**检索**

- 对中文和代码标识符做词法切分：中文按重叠二元组，拉丁标识符保留完整词和组件；排序采用 BM25 风格词频、文档频率和长度归一化，并给路径命中少量加权。
- 每次查询先按本机身份和项目范围过滤，再对命中的有效记录扫描来源文件、核对当前内容哈希。文件更新、删除、被忽略或失去读取权限后，失效记录立即退出结果；新内容需要再次 `sync` 才进入索引。
- 直接读取只接受记录 ID，不接受任意文件路径；越权项目返回 `FORBIDDEN`，失效记录返回 `NOT_FOUND`。
- 当前面向本机小语料，查询成本随文件总量增长；没有向量检索、预计算倒排或文件监听。

**数据可靠性**

- 文件扫描和 Git 读取在事务外完成；扫描失败不会把原索引误判为已删除。同步在一个事务内写入源版本、记录、索引和幂等回执。
- 同步使用 `request-key` 幂等：同一 key 返回已提交结果，key 不能用于另一来源配置；并发更新使用条件版本检查。
- 文件更新保留被替代版本以便追溯，但保留版本不通过 MCP 暴露。删除来源时在事务内清理原文快照、记录、派生索引和幂等回执，只留下元数据删除标记与审计。
- 归档批次按页原子提交：`after_cursor` 必须等于已提交游标，页面指纹覆盖完整批次（含被跳过事件），重复页识别为幂等重放；不合法或冲突的事件身份会使事务回滚且游标不前进。
- 删除标记到达后清除对应会话的证据，并把会话键记入墓碑，阻止旧页或后续事件复活数据。
- 写入事件与创建提取任务尚未实现；当前没有事件队列、任务租约或提取幂等逻辑。

## 已知限制

- 本机单用户，身份来自进程配置（当前 OS uid）；没有认证主体、团队权限或跨团队共享。
- 检索是词法匹配，命中相同词项不代表问题一定有答案；回答者必须读取来源核实。
- 自定义 `SourceScanner` 是受信任代码，不是沙箱；它必须自己执行输入授权和文件系统安全检查。
- 内置扫描器不跟随符号链接，使用 `O_NOFOLLOW` 并复核祖先目录与文件身份；Node 路径 API 仍无法对恶意进程反复切换父目录提供完整的 `openat` 级原子隔离，团队服务前需要加固。
- 没有对话记忆、提取队列、模型提供方、经验反馈、自动 skill 修改或 Agent Stats 用量接入；没有批量读取历史会话。
