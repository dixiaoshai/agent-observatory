# Agent Knowledge 架构决策

状态：第一阶段知识检索、共享归档证据消费与本项目主动拉取 worker 已实现；自动记忆提取和持续改进为后续阶段。更新日期：2026-11-15。

## 本项目主动拉取（follow）

采用无 hook 的 Trace 常驻日志扫描，Knowledge 在自身项目维护独立的自动拉取 worker、消费进度、重试与授权；Trace 只提供只读 v1 事件流，不保存 Knowledge 的投递状态、不运行本项目命令。`src/follow/` 实现严格配置、回环 HTTP 客户端、状态校验和单 worker 租约；每页复用 `ArchiveEvidenceStore.importBatch`，证据投影、墓碑与归档游标在同一本地事务提交。worker 与 MCP 连接生命周期分离，关闭聊天不停止同步；也可在不运行 MCP 时单独运行。证据仍进入独立证据库，不自动转为确认知识，也不引入模型提取。目标接口、故障语义见[消费方约定](../../agent-trace/docs/consumer-follow.md)和 [TODO](../../../docs/ROADMAP.md)。

## 2026-11-14 共享归档边界更新

执行日志的采集、原始事件快照、统一事件和删除流移交独立兄弟模块 `agent-trace`。Agent Knowledge 通过版本化 JSON content 批次消费，维护独立事件引用、事务游标与项目授权；Agent Stats 独立消费 metadata 批次。双方不读取归档内部 SQLite，也不写入对方数据库。以下原设计中的宿主采集职责应按本更新理解，文档/代码文件扫描仍由 Agent Knowledge 负责。

归档证据是历史观察，不是活跃 knowledge/memory。content 事件可能把超大正文外置为 `content_ref`（绝对路径、字节数、SHA-256，媒体类型固定 `text/plain`）；导入时校验引用与 `raw` 一致，检索文本仍来自 `body`，正文读取需按引用校验本地文件。`ArchiveEvidenceStore` 单独维护证据表和按 owner/project 限制的读取，数据库为 `<config.database>.archive-evidence.sqlite`；不套用文档当前文件哈希校验，因此原日志清理后仍可核对快照。数据库与现有异步知识事务分开，避免同进程多连接同步锁等待。MCP 增加只读 `search_archive/read_archive_event`；导入只通过 CLI，不接受 MCP 写入。经验候选生成、验证、晋升及关联失效传播仍未实现。

消费者处理幂等页、游标冲突、未知类型和删除标记；未知类型的原始证据不执行。仅本机身份/项目限制，尚无团队多用户认证或按授权过滤导出流。`record_hash` 为归档给出的源行哈希声明，批次中的 parsed raw 不足以独立重算该原始字节哈希。Agent Knowledge 自身未来模型调用用量仍可通过 UsageSink 输出；不反向作为外部宿主原始事件重复采集。

## 2026-11-15 项目范围改为消费过滤

`allowed_project_ids` 对归档证据是**消费范围**，不再是投递或整页门槛。Trace 转向全量采集后，content 面可能包含 Knowledge 未配置的新 `project_id`（例如兜底的 `unscoped`）；`importBatch` 对名单外事件（含 `session.deleted`）直接跳过，不写证据、不写墓碑，仍在同一事务内把游标提交到 `next_cursor`，因此页面不会因项目不匹配而永久失败或停摆。页面级校验保持：信封/schema、`archive_seq` 递增与范围、游标连续性与页面指纹；指纹按完整批次计算，重放语义不受消费范围影响。`scope()`、CLI `--project` 与 MCP `project_id` 对“显式查询名单外项目”仍返回 `FORBIDDEN`，读取侧授权没有放宽。缩小或扩大消费范围都不会迁移既有数据：缩小时已导入证据保留（不会自动清理），扩大时被跳过的历史不会回填（游标已前进）；需要重建时显式删除证据库并从 0 回放。

## 决策与范围

自主实现统一的知识与记忆内核，先服务本机 Codex，再扩展其他 agent 和团队部署。参考现有实现的设计机制；产品内核由 Agent Knowledge 自己维护。存储、解析、MCP 和模型调用可以使用通用库，具体依赖与版本在实现相应模块时核对并锁定。

各入口调用同一套应用服务、生命周期策略和存储逻辑。CLI 用于导入和管理，MCP 用于 agent 调用；执行日志采集由 Trace 负责，Knowledge 的后续同步 worker 只主动拉取已有事件。未来上下文注入适配与 UI 可复用本项目内核，不把采集职责重新放回 Knowledge。

## 技术结构

首版本地使用 TypeScript 和 SQLite。SQLite 保存权威记录、事件、版本、任务和审计；搜索索引是可重建的派生数据。原始资料仍由源文件及其版本定义，数据库中的来源快照用于核验已提取内容。

```text
文档/代码适配器       Codex/其他 agent 适配器
       │                       │
       └────── 标准化输入 ──────┘
                     │
       Core：来源、事件、记录、证据、生命周期
                     │
       SQLite：事务、版本、队列、检索索引
                     │
       Retrieval：过滤、召回、排序、预算、引用
                     │
            CLI / MCP / 后续 HTTP 与 UI

Worker：从持久化任务提取知识和记忆，写回候选记录
```

本机各组件先在同一代码库内组织。MCP 进程和 worker 可以独立启动，共用数据目录；数据库迁移、短事务、锁等待与任务租约需验收。宿主 hook 只提交事件和短任务，模型处理在 worker 中运行。

## 模块责任

| 模块 | 责任 |
| --- | --- |
| `core` | 统一记录信封、来源、证据、版本、时间与生命周期规则；不依赖数据库、宿主或传输协议 |
| `application` | 用例编排与所需接口定义；事务边界、来源失效传播和 Context Pack 组装 |
| `storage` | 实现应用层存储接口；SQLite 迁移、事务、任务领取与重试 |
| `ingestion` | 文件发现、路径限制、内容哈希、增量更新与删除 |
| `extraction` | 文档/对话提取器，AST 解析器；模型输出校验与来源检查 |
| `retrieval` | 权限和状态过滤、词法召回、后续语义/关系召回、上下文预算 |
| `learning` | 候选经验、冲突处理、验证反馈、晋升/撤回与影响传播 |
| `adapters` | Codex 宿主事件转换，以及后续其他 agent 的能力差异 |
| `interfaces` | CLI、MCP、后续 HTTP/UI；调用同一应用服务 |
| `telemetry` | 模型用量事件和输出适配器；后续对接 Agent Stats |

模块是代码边界，首版无需拆成独立微服务。

当前实现包括 `core`、`application`、`storage`、`ingestion`、`retrieval`、`interfaces` 和组合入口 `bootstrap`。应用端口仅实现当前用例需要的来源、记录、审计、事务、扫描及词法索引；事件/任务仓储、提取器、反馈、模型与 UsageSink 待对应阶段实现。当前存储契约测试只覆盖第一阶段，不能代表队列、租约或完整记忆生命周期已通过验收。

第一阶段的派生检索表保存有效记录的文本和路径，适配器读取授权范围内的语料，调用独立 BM25 风格词法排序。每次查询/读取按来源扫描并核对当前文件哈希，失效内容立即退出返回结果；新内容仍需 CLI 同步后进入索引。这有意面向本机小语料，查询成本随文件总量增长。后续可换为预计算倒排/向量检索及更细粒度文件验证，不改变应用端口。

## 高内聚与低耦合约束

依赖由入口/适配器指向应用用例，再指向领域。存储、模型、搜索与遥测实现由组合入口注入；领域与应用代码不导入具体数据库驱动、宿主 SDK 或 Agent Stats 实现。

对外只暴露模块公共接口和领域数据；其他模块不得跨目录访问内部 helper。按“来源管理、检索、经验生命周期”等完整责任组织实现，避免把一个用例散落成大量只有转发逻辑的微模块。

同一用例的规则集中在应用/领域层：MCP、CLI、hook 和未来 UI 不各自维护一套保存、权限或晋升规则。新数据源、agent 和数据库通过增加适配器接入。

## 可替换的存储接口

接口定义放在应用层的 ports 中，由存储层实现。首版按实际用例定义以下窄接口；方法使用领域对象、游标和异步返回值，SQL、连接句柄和数据库专属错误保持在适配器内部。

| 接口 | 契约 |
| --- | --- |
| `SourceRepository` | 来源与不可变源版本、内容哈希、版本检查 |
| `EventRepository` | 会话事件、幂等键、顺序与增量游标 |
| `RecordRepository` | 记录版本、状态、归属、时间、证据与关系 |
| `JobRepository` | 原子领取、租约、尝试次数、超时恢复 |
| `AuditRepository` | 审计追加、删除标记及生命周期追踪 |
| `UnitOfWork` | 在同一事务内提供上述仓储；统一提交和回滚语义 |

`UnitOfWork` 保证事件写入与任务创建原子提交；任务领取、条件版本更新和唯一约束也属于后端必须实现的行为。事务回调内不执行模型调用、外部网络或遥测发送，避免长事务和重试时的重复外部动作。

`LexicalSearchIndex`、`VectorIndex`、`RelationReader` 分别提供派生检索能力。首版词法/关系实现可以使用 SQLite；查询用例仅依赖对应接口。更换权威数据库与更换检索引擎是独立操作；外部索引使用版本和删除状态校验，索引延迟不能让已撤回内容重新进入有效结果。

选择后端由配置和组合入口完成。未来增加 PostgreSQL 等实现时，需提供自己的 schema 迁移与数据迁移程序，并通过共同的仓储契约测试：原子事务、幂等、版本冲突、租约并发领取、游标稳定性、作用域与删除一致性。首轮提供 SQLite 实现与可复用验收契约；第二种数据库的等价性在其实现后验证。

## Agent Journal 边界

每日回顾与跨天经验整合由独立 [Agent Journal](../../agent-journal/README.md) 负责；它消费 Trace content、维护自己的 cursor、日缓冲和模型调用。Knowledge 不读取其数据库、不调用其命令，只在 Journal 把日报写入 Markdown 目录后按普通 source 索引。该 source 需要 `generated: true` 标记，把模型生成物与来源事实分开（尚未实现）；在实现前不索引日报，避免搜索把总结当原始证据引用。

## Agent Stats 接入边界

保留 `UsageSink` 输出接口；Agent Knowledge 自身的模型调用在统一 provider 包装层生成用量事件，数据源/宿主适配器提供可关联的外部会话标识。Agent Stats 是可选消费方，不参与保存记忆、检索或事务决策。这项未来用量事件接入与已实现的共享执行归档消费是两条独立集成路径。

拟定事件包含 `schema_version`、`event_id`、`producer`、`operation_id`、`request_id`、`attempt_id`、`parent_operation_id`、`session_id`、`external_session_id`、`external_turn_id`、`project_id`、`agent_id`、`operation`、`provider`、`model`、`started_at`、`duration_ms`、`status` 和 `usage`。`operation` 区分知识提取、记忆提取、embedding 和后台整理。token 字段区分 input/output/cached/reasoning，缺失值使用 null 并附原因；外部请求标识无法取得时也保留 null。计费包含关系由 provider 适配器明确，不能直接把所有字段相加。

UsageSink 首版允许空实现或本地导出，后续增加 Agent Stats 适配器；失败不阻塞主流程，投递时采用有界重试/去重并报告丢弃。业务任务重试对应独立 attempt，用量重放保留同一 event_id。仅发送用量及关联元数据，默认不包含提示词、知识正文或密钥。

宿主 agent 的 token 用量与 Agent Knowledge 自身模型用量分开归属。外部身份同时保留 source/instance/session/turn，实际可取得请求标识时再做请求级去重；包含关系未知时分别展示，不强行合计。

已只读核对本机 Agent Stats 的 `docs/RUNNING.md`、`agent_stats/server.py` 与来源适配器：当前从 Codex rollout JSONL 读取累计 token 快照并做差；HTTP 的 `POST /api/refresh` 仅重新读取配置路径，没有外部模型用量写入接口。后续需为 Agent Knowledge 增加独立的用量事件格式及 Agent Stats 来源适配器，或由双方约定新增写入 API；本轮不修改 Agent Stats，不直接写入它的内部数据库。现有宿主日志统计与新增 Agent Knowledge 自身用量分别保留来源，避免重复统计。

## 第一轮 skill

随第一轮提供 [Agent Knowledge 使用 skill](../skills/agent-knowledge/SKILL.md)，定义何时检索、如何读取来源、如何处理过期或矛盾内容，以及何时保存事实或候选经验。技能只调用应用层经 MCP 暴露的能力，不直接访问数据库；稳定团队规则仍由宿主指令管理。

首轮验收既覆盖显式调用，也覆盖宿主自动选择；工具不可用时明确反馈，不虚构检索结果。skill 的自动选择属于宿主行为，不保证每轮都被调用；要求确定触发的采集/注入由宿主适配器负责。

## 数据与可靠性

统一元数据包含记录 ID、种类、归属、作用域、状态、时间、来源引用和 schema 版本。知识、记忆、经验和流程提案保留各自的结构字段，不能只用一段摘要表达全部语义。

核心表族包括来源与源版本、会话与事件、记录与记录版本、证据链接、关系、反馈、任务、审计和删除标记。搜索索引与关系图均能从有效记录重建。首版关系使用 SQLite 表存储，图数据库作为后续可评估的存储扩展。

- 写入事件与创建提取任务处于同一事务；以宿主、会话、事件标识唯一约束去重。
- worker 使用有期限的任务租约，允许崩溃恢复；派生写入由输入版本和提取器版本控制幂等。
- 提取结束前复核来源版本；过期结果丢弃或重新排队。
- 新事实引用被替代记录，保留历史及有效时间；重复信息不自动增加事实可信等级。
- 证据撤回、改变或删除时，相关派生结论标为待复核并退出默认有效结果，再按策略重提取；来源未变的其他证据也需重新评估。
- 删除事务先写入删除标记并排除检索，后续清理原文快照、派生记录和索引；旧任务检查删除标记，禁止重新生成。

## 经验与持续改进

原始对话是事件，摘要是压缩表示，经验是有条件的可复用结论。明确用户偏好和项目决策可以按策略启用；推断保留为候选；修复经验需要匹配的测试、实际结果或明确确认。

经验流转：提取候选 → 核对来源与适用条件 → 验证 → 激活 → 使用反馈 → 必要时撤回或重新验证。模型评分、重复调用与频繁访问用于排序，不能替代正确性证据。首版由人工或外部测试提供验证结果，暂不做任意代码的自动测试执行。

后台整理只提交候选变更。Skill 和长期流程更新需独立验证、版本记录及回滚点。先实现经验与上下文改进，再评估自动流程优化。

## 检索与边界

先实现支持中文和代码标识符的词法检索、有效性过滤与引用。后续根据固定问题集的失败案例加入向量和关系扩展；多路召回必须在相同授权范围内执行。

Context Pack 按任务打包相关项目事实、近期状态、经验和来源。预算控制在内容选取阶段执行，保留足够的引用，提供继续读取原文的入口。

首版本机身份来自进程配置，所有查询和直接读取都检查项目范围。团队部署阶段增加认证主体、权限决策和跨团队显式共享；查询参数只能缩小授权范围。当前本机作用域检查不代表已经具备多人权限系统。

## 第一轮交付

1. 核心 schema 与迁移；合成文档/代码/对话样例；来源与证据存储。
2. 文件增量导入、词法检索、来源读取，提供 CLI 和 MCP。
3. Codex 事件适配、持久化任务、显式记忆保存与跨会话召回。
4. 接通可配置的模型提取器，加入经验验证、反馈和失效传播。
5. 交付并联调 Agent Knowledge skill；同时验证 SQLite 存储契约和用量输出接口，Agent Stats 实际集成后续完成。

验收继续使用 [MVP 用例](mvp.md)。AST 深层调用图、向量检索、复杂时间推理、自动 Skill 发布和团队服务在基础链路通过后分别增加。
