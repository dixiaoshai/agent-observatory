# Agent Knowledge 本机 Codex 试点方案

## 目标与范围

第一版验证三个结果：指定文档和代码可被检索；试点对话能沉淀有来源的记忆；新会话能复用适用的经验。

实现策略：自主实现 Agent Knowledge 的数据模型、记忆生命周期、任务处理和检索接口；参考其他项目的机制，使用通用存储、解析和协议库。模块划分见 [架构决策](architecture.md)。

本机版本仅供当前操作系统用户使用。数据模型保留项目、团队和组织作用域；多人服务必须完成身份认证和服务端权限实现后另行验收，不能把本机版本直接开放为团队服务。

## 数据类型

| 类型 | 内容 | 生效条件 |
| --- | --- | --- |
| knowledge | 原文片段，以及带引用的派生说明 | 对应源文件版本仍有效；派生说明标注为模型生成 |
| memory | 用户明确偏好、项目事实、决策、待办 | 明确事实可启用；模型推断保留为候选 |
| lesson | 场景、问题、原因、解决步骤、适用边界 | 具备匹配的验证证据后启用 |
| skill proposal | 从重复成功经验提炼的流程修改 | 经独立验证后版本化发布，并保留回滚点 |

所有记录至少包含：`id`、`schema_version`、`kind`、`content`、`source_refs`、`created_at`、`updated_at`、`status`、`scope`、`owner_id`、`project_id`、`team_id`、`org_id`。未使用的作用域字段为空。

附加字段：

- 来源引用：文件路径与行号或会话/事件 ID，以及内容哈希；有 Git 版本时记录 commit。
- 记忆与经验：适用条件、证据、冲突记录、被替代关系和可选失效时间。
- 状态：`candidate`、`active`、`superseded`、`revoked`。
- 提取溯源：提取器版本、模型标识、输入事件范围。模型给出的置信度不能替代验证证据。

源文件仍是事实依据。生成摘要、检索命中和聊天内容均作为数据使用，不能自动成为新的执行授权。

## 逻辑接口草案

以下为待实现的应用接口，并非已安装的 MCP 工具。写入操作接收幂等键；身份由本机适配器或未来服务端会话提供，不能由调用者任意指定。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `ingest_source` | 已配置源 ID、增量同步请求 | 新增/更新/删除数量、源版本、错误 |
| `search_context` | query、允许范围内的项目过滤、类型、结果数量 | 有权限且有效的结果、来源、适用条件 |
| `read_record` | record ID | 经相同权限检查后的完整记录与证据 |
| `append_events` | 会话 ID、事件 ID、标准化事件 | 已持久化位置、重复数量、提取任务状态 |
| `record_memory` | 内容、类型、证据引用、请求作用域 | 通过策略检查后的记录或候选 ID |
| `record_feedback` | 记录 ID、任务结果、证据引用 | 反馈 ID；验证状态由策略决定 |
| `revoke_record` | 记录 ID、原因 | 撤回状态，后续检索立即排除 |
| `delete_source` | 源 ID、删除范围 | 原始数据、派生记录和索引的清理结果 |

第一阶段只暴露搜索、读取工具；目录导入由本地 CLI 完成。目录由配置限定，不能通过搜索工具读取任意路径。

第一轮包含 [Agent Knowledge skill](../skills/agent-knowledge/SKILL.md)。知识检索阶段先验收查询与引用流程；记忆接口实现后再验收保存、纠错和经验反馈。安装、工具连接和完整行为联调属于交付验收。

存储通过领域仓储、`UnitOfWork` 和派生检索接口访问。首版 SQLite 与未来数据库共享行为契约；用量通过可选 `UsageSink` 输出，为后续 Agent Stats 接入保留关联字段和适配层，详见 [架构决策](architecture.md)。

## 文档与代码导入

1. 首批支持 Markdown、UTF-8 文本和常用代码文本；PDF、Office 和远程数据源后续增加。
2. 明确允许目录、文件大小和扩展名；排除凭据文件、依赖、构建产物和被忽略路径，符号链接不得越出允许目录。
3. 保存带行号的原文片段和内容哈希；代码先提供可追溯检索，函数关系和跨文件架构分析逐步增加。
4. 初次导入后提供增量同步；文件修改使旧版本失效，源文件删除使旧片段退出默认检索。
5. 基础检索需支持中文和代码标识符。以试点问题验证效果，不能仅以英文关键词示例通过验收。

## Codex 接入

知识与记忆工具通过本地 STDIO MCP 提供。会话引导说明检索时机和引用方式；提供 MCP 工具本身不保证每回合自动检索，因此需要验证任务级调用和自动注入。

官方文档依据：

- [MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)：Codex 支持本地 STDIO 和 Streamable HTTP 服务器。
- [Hooks](https://learn.chatgpt.com/docs/hooks)：可提供会话和回合事件；`transcript_path` 指向的聊天格式不是稳定接口。

接入适配器必须针对本机客户端实测事件是否触发、输入结构和上下文注入是否生效。解析不支持的 transcript 版本时明确报告，不能静默宣称采集成功。无法自动采集时提供显式导入路径，并标明覆盖范围。

采集采用“短 hook 持久化事件或任务 → 本地 worker 异步提取”，不能让 hook 等待完整模型提取。退出事件只作为补充信号；以已持久化的增量事件支持恢复，防止退出时丢失后台任务。

每个试点回合都应有可观察的处理结果：生成候选、没有可复用信息、跳过或失败。允许一个回合产生零条记忆。

子代理事件如接入，须保留父会话与子代理标识，避免与主会话重复计入。首版先验收主会话，再扩大覆盖范围。

## 对话提取与持续改进

- 先采集明确选择的试点会话，默认不扫描全部历史对话。
- 用户明确陈述、agent 推断、工具结果分别标注；相互冲突的内容不能无条件覆盖。
- 记忆提取使用可配置模型接口。模型提供方、凭据和数据传输范围在接通时确定；缺少模型时保留待处理任务，不能用占位结果冒充自动提取。
- 事件先落盘，后台处理可重试；同一事件重复投递只记一次。
- 经验需要可复核证据，例如对应代码版本的测试结果或用户明确确认；“agent 说成功”不构成充分证据。
- 反馈先影响经验的有效性、排序和适用范围。Skill 的修改需版本化、验证和回滚；原始任务失败不能直接触发全局规则变更。
- 撤回立即影响检索；删除还需清理原始事件、派生内容和索引，避免后台任务从旧事件重新生成。保留期和备份删除策略在团队版本落地。

## 验收用例

| 场景 | 必须观察到的结果 |
| --- | --- |
| 中文提问与代码检索 | 在 10 个预先标注答案和来源的试点问题中，至少 8 个在前 5 条结果中找到正确来源；另测无答案问题不编造来源 |
| 新会话引用知识 | Codex 在一个全新会话中通过工具获取原文并给出正确引用，不能借用旧聊天上下文 |
| 文件更新与删除 | 更新后默认结果为新版本；删除后旧片段不再返回 |
| 对话决策复用 | 第一会话明确一个项目决策，提取完成后，第二会话准确召回且能追溯原事件 |
| 推测和冲突 | 未验证猜测不能成为 active 事实；相反决策保留替代关系 |
| 重试与恢复 | 同一事件提交两次只处理一次；模拟提取失败和重启后仍能继续 |
| 有效经验与撤回 | 已验证修复能在适用任务中召回；撤回后搜索和直接读取均不再提供可用内容 |
| 作用域隔离 | 不同项目的私有数据不会因查询或直接传 ID 越界返回；团队上线前另做不同身份验收 |
| 删除完整性 | 删除会话来源后，派生记忆和检索索引被清理，旧提取任务无法重新生成 |
| skill 使用知识 | 显式调用能检索并引用有效来源；在代表性任务中检查自动选择，未触发时可追踪宿主行为；无工具时不虚构结果 |
| skill 保存经验 | 未验证经验保留候选；明确事实带原始引用；只在调用成功后报告已保存 |
| 存储接口契约 | SQLite 实现通过事务、幂等、条件版本更新、并发任务领取和删除一致性检查；业务模块无 SQLite 驱动依赖 |
| 用量输出边界 | 可替换 sink 接收关联事件；未知 token 不写成零；失败不阻塞业务；重放不重复计数，正文不进入用量事件 |

## 开发顺序

1. 定义记录、来源、作用域和迁移结构；准备合成文档与中文/代码检索样例。
2. 实现目录同步、索引、搜索和来源读取，提供本地 CLI 与 MCP。
3. 在本机 Codex 新会话中验证工具调用，记录客户端版本、调用证据和引用结果。
4. 实现事件适配、持久化队列、提取器和记忆管理，验证跨会话复用。
5. 增加经验反馈和验证，再开展第二种 agent 与团队服务。
6. skill 随对应能力同步联调；首轮交付包含完整使用流程、存储契约与可选用量输出，Agent Stats 对接单独验收。
